Agrupamiento y Análisis Condicional en SQL

Clase 4A: Cláusulas GROUP BY y HAVING

Objetivo de la clase: Aprender a agrupar registros y filtrar resultados consolidados en SQL de forma eficiente.

Utiliza los botones inferiores o las flechas del teclado (← / →) para avanzar en la presentación.

Planteo del Problema

El requerimiento de Adscripción

Imaginemos el siguiente pedido institucional:

"Necesitamos un reporte que muestre el promedio general de calificaciones de CADA ASIGNATURA de forma separada."

Limitación previa: Con las herramientas anteriores (como SELECT AVG(nota) FROM Inscripciones;) solo obtenemos un promedio general único. Hacer una consulta separada por materia sería ineficiente.

Solución nativa de SQL: La instrucción GROUP BY.

Exposición Teórica: GROUP BY

Estructura de la consulta

SELECT id_asignatura, AVG(nota) AS promedio_materia
FROM Inscripciones
GROUP BY id_asignatura;

¿Cómo actúa el motor?

  1. Toma la tabla Inscripciones.
  2. Agrupa (colapsa) en un bloque las filas con el mismo valor en id_asignatura.
  3. Aplica la función de agregación AVG() a cada grupo generado.

⚠️ Regla de Oro: Toda columna en el SELECT que no esté agregada (como COUNT o AVG) debe figurar obligatoriamente en el GROUP BY.

El dilema del filtrado

¿Por qué falla WHERE con funciones de agregación?

Segundo requerimiento: Listar solo aquellas asignaturas cuyo promedio sea reprobatorio (< 6).

-- ❌ ERROR DE SINTAXIS
SELECT id_asignatura, AVG(nota)
FROM Inscripciones
WHERE AVG(nota) < 6 
GROUP BY id_asignatura;

Causa técnica: El motor ejecuta WHERE fila por fila antes de agrupar. En esa fase, las funciones agregadas aún no existen.

La Solución: Cláusula HAVING

Filtrando grupos consolidados

-- ✔️ CONSULTA CORRECTA
SELECT id_asignatura, AVG(nota) AS promedio
FROM Inscripciones
GROUP BY id_asignatura
HAVING AVG(nota) < 6.0;

Secuencia lógica de ejecución del motor SQL:

1) FROM → 2) WHERE → 3) GROUP BY → 4) HAVING → 5) SELECT → 6) ORDER BY

Ejercicio 3: Promedio por Estudiante Ordenado

Consigna: Calcular el promedio de notas de cada estudiante (id_estudiante) y ordenar el resultado de mayor a menor según dicho promedio.

Este ejercicio integra el uso de agrupamientos junto con la cláusula de ordenamiento final.

Solución: Ejercicio 3

Promedio por Estudiante Ordenado

FROM Inscripciones

Ejercicio 4: Identificación de Asignaturas con Bajo Rendimiento

Consigna: Mostrar los códigos de asignatura (id_asignatura) que tengan un promedio general de notas estrictamente menor a 6.0.

Analiza detenidamente si debes utilizar WHERE o HAVING para cumplir esta condición sobre un valor agregado.

Solución: Ejercicio 4

Asignaturas con Bajo Rendimiento (HAVING Básico)

SELECT id_asignatura, AVG(nota) AS promedio_materia
FROM Inscripciones
GROUP BY id_asignatura
HAVING AVG(nota) < 6.0;

1055.5000

Práctica Guiada

Ejercicio 5: Filtro Combinado de Fila y Grupo

Consigna: Obtener el total de inscripciones por asignatura (id_asignatura) considerando únicamente las inscripciones del año 2024 (anio_cursado = 2024), y mostrando solo aquellas asignaturas que registren más de 3 inscriptos en ese año.

Este es el ejercicio de integración definitivo para evaluar la diferencia conceptual entre ambas etapas de filtrado.

Solución: Ejercicio 5

Filtro Combinado (WHERE + HAVING)

SELECT id_asignatura, COUNT(*) AS total_2024
FROM Inscripciones
WHERE anio_cursado = 2024
GROUP BY id_asignatura
HAVING COUNT(*) > 3;

Resultado esperado de la consulta:

id_asignatura total_2024
1017
1027
1035
