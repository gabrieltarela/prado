Consideraciones antes de comenzar:

Alias de columnas

Usar alias (AS) para que las columnas del resultado tengan nombres descriptivos. Por ejemplo, en el Pedido 1 mostrar nro_factura en lugar de id_venta.

Notación tabla.campo

Usar alias de tabla y la notación tabla.campo para que quede claro a qué tabla pertenece cada columna.

Regla de oro del GROUP BY: toda columna que aparezca en el SELECT y que no esté dentro de una función de agregación (COUNT, SUM, AVG, etc.) debe figurar obligatoriamente en la cláusula GROUP BY. 
SELECT p.nombre_producto AS producto, p.precio_venta
FROM Productos p;

SELECT
  v.id_venta AS nro_factura,
  v.fecha_venta,
  e.nombre AS vendedor
FROM Ventas v
JOIN Empleados e ON v.id_empleado = e.id_empleado
ORDER BY v.id_venta;
Explicación técnica: Consulta de modelado inicial. Relaciona 2 tablas mediante la clave foránea id_empleado. Como toda venta tiene un vendedor asignado (id_empleado es NOT NULL), el JOIN convencional devuelve todas las filas sin descartar ninguna.

Recursos Humanos — Consulta SQL & Resultado

SELECT
  e.id_empleado,
  e.nombre AS vendedor,
  COUNT(v.id_venta) AS cantidad_ventas,
  SUM(v.monto_total) AS monto_total_vendido
FROM Empleados e
JOIN Ventas v ON e.id_empleado = v.id_empleado
GROUP BY e.id_empleado, e.nombre
HAVING COUNT(v.id_venta) > 1;
Explicación técnica: La condición sobre el total agrupado (COUNT) no se puede evaluar en WHERE (filtra filas antes de agrupar). Debe ir obligatoriamente en HAVING. Se cumple la regla de incluir en GROUP BY las columnas no agregadas del SELECT.

Pedido 4Solución

Gerencia General — Consulta SQL & Resultado

SELECT
  v.id_venta AS nro_factura,
  v.fecha_venta,
  v.monto_total,
  c.nombre AS nombre_cliente,
  e.nombre AS vendedor
FROM Ventas v
LEFT JOIN Clientes c ON v.id_cliente = c.id_cliente
JOIN Empleados e ON v.id_empleado = e.id_empleado
WHERE v.monto_total > (
  SELECT AVG(monto_total)
  FROM Ventas
)
ORDER BY v.monto_total DESC;
Explicación técnica: Combina subconsulta escalar en WHERE para calcular dinámicamente el promedio ($45.000). Utiliza LEFT JOIN con Clientes para no descartar ventas a Consumidor Final que superen dicho monto.

Atención al Cliente — Consulta SQL & Resultado

SELECT
  c.nombre AS nombre_cliente,
  v.fecha_venta,
  e.nombre AS vendedor,
  p.nombre_producto,
  dv.cantidad
FROM Ventas v
LEFT JOIN Clientes c ON v.id_cliente = c.id_cliente
JOIN Empleados e ON v.id_empleado = e.id_empleado
JOIN Detalle_Ventas dv ON v.id_venta = dv.id_venta
JOIN Productos p ON dv.id_producto = p.id_producto
ORDER BY v.fecha_venta, v.id_venta;
Explicación técnica: Integra las 5 tablas de la base mediante relaciones de clave foránea. La seguridad y confidencialidad se garantiza proyectando expresamente solo los campos autorizados y omitiendo SELECT *.

Tramo 3Auditoría y seguridad de la información
Pedido 6Solución

Auditoría Comercial — Consulta SQL & Resultado

SELECT
  c.id_cliente, c.nombre AS nombre_cliente,
  v.id_venta AS nro_factura, v.fecha_venta, v.monto_total
FROM Clientes c LEFT JOIN Ventas v ON c.id_cliente = v.id_cliente
UNION
SELECT
  c.id_cliente, c.nombre AS nombre_cliente,
  v.id_venta AS nro_factura, v.fecha_venta, v.monto_total
FROM Clientes c RIGHT JOIN Ventas v ON c.id_cliente = v.id_cliente
ORDER BY nro_factura;
Explicación técnica: Simula un FULL OUTER JOIN. Un LEFT JOIN obtiene clientes sin ventas (Diego) y un RIGHT JOIN obtiene ventas sin cliente (1003). UNION apila ambas consultas eliminando las filas duplicadas.
